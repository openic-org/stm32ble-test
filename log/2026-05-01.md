# Session Log — 2026-05-01

## What was done

### Phase 2 — Client Board Adaptation (complete)

Adapted the client firmware for the custom STM32WB09TE board (no buttons, no LEDs, different UART/SWD pinout, external LSE crystal).

#### Key findings on existing code

- **USART1 pins already correct**: The reference example used PA1 (TX) / PB0 (RX) via AF2/AF0, which matches the custom board. No change needed.
- **LSE already enabled**: `CFG_LSCLK_LSE = 1` and `RCC_LSE_ON` were already in the reference code. PB12/PB13 are fixed-function OSC32 pins — no GPIO config needed.
- **SWD already set up for PA2/PA3**: `lowPowerIOSetup()` already had pull-ups on PA2 and PA3.

#### Changes made

**`client/Makefile`**
- Replaced `-DNUCLEO_WB09KE` with `-DCUSTOM_WB09TE`
- Removed `stm32wb0x_nucleo.c` BSP source
- Removed `-I.../Drivers/BSP/STM32WB0x-nucleo` include path

**`client/Core/Inc/app_conf.h`**
- `CFG_LED_SUPPORTED = 0`
- `CFG_BUTTON_SUPPORTED = 0`

**`client/Core/Inc/main.h`**
- Removed `#include "stm32wb0x_nucleo.h"`

**`client/Core/Src/main.c`**
- Added `UART_HandleTypeDef huart1` global definition (was previously provided by BSP)
- Added `MX_USART1_UART_Init()` — initializes USART1 at 115200 8N1
- Added `__io_putchar()` using LL polling — replaces BSP's implementation so `printf` / `DT_INFO_MSG` continue to work
- Added `MX_USART1_UART_Init()` call in `main()` initialization sequence

**`client/Core/Src/stm32wb0x_it.c`**
- Removed `extern UART_HandleTypeDef huart1` (unused; IRQ handler uses LL directly)
- Removed `GPIOA_IRQHandler` and `GPIOB_IRQHandler` (called BSP button handlers, no buttons on custom board)

**`client/STM32_BLE/App/app_ble.c`**
- Removed `BSP_COM_Init` block from `APP_BLE_Init()`
- Removed all `BSP_LED_On/Off` calls from `Scan_Request()`, `Connect_Request()`, `Connection_Update()`, and GAP proc complete handler
- Removed `UTIL_SEQ_WaitEvt(CFG_IDLEEVT_CONNECTION_COMPLETE)` from `Connect_Request()` — this event was never set in the reference code, causing `Connect_Request` to hang indefinitely in the wait loop; removed to simplify flow
- Added auto-scan on boot: `UTIL_SEQ_SetTask(CFG_TASK_START_SCAN_ID)` at end of `APP_BLE_Init()`
- Added auto-rescan on disconnect: schedule `CFG_TASK_START_SCAN_ID` and reset `ButtonTransferReq = OFF` in `HCI_DISCONNECTION_COMPLETE_EVT_CODE`

**`client/STM32_BLE/App/gatt_client_app.c`**
- Removed `BSP_LED_On/Off` calls from `DTC_Button1TriggerReceived()`
- Added auto-TX start at end of `PROC_GATT_ENABLE_ALL_NOTIFICATIONS`: sets `ButtonTransferReq = ON` and schedules `CFG_TASK_WRITE_DATA_WO_RESP_ID` immediately after service discovery completes

#### Boot sequence (new, no buttons needed)

```
Power on
  → MX_APPE_Init() → APP_BLE_Init()
  → Scan_Request() [auto on boot]
  → DT Server found → aci_gap_terminate_proc(GAP_GENERAL_DISCOVERY_PROC)
  → GAP proc complete → Connect_Request() [aci_gap_create_connection]
  → connection_complete_event() → GATT_CLIENT_APP_Discover_services()
  → client_discover_all(): disc services → disc chars → disc descs → enable notifs
  → auto-TX starts: ButtonTransferReq = ON, SendDataWrite() scheduled
  → disconnects → reset ButtonTransferReq, auto-rescan
```

## Phase 3 — Throughput Optimizations (complete)

### Changes made

**`server/Core/Inc/app_conf.h` and `client/Core/Inc/app_conf.h`**
- `CFG_BONDING_MODE = 0` — disables pairing/bonding overhead
- `CFG_LPM_SUPPORTED = 0` — disables low-power manager so the CPU stays at full speed

**`server/STM32_BLE/App/app_ble.c`**
- `LinkConfiguration()`: added `hci_le_set_phy(2M)` call with `gap_cmd_resp_wait()` — server requests 2M PHY immediately on connect, waits for completion before continuing
- `LinkConfiguration()`: schedules `CFG_TASK_CONN_INTERV_UPDATE_ID` so 7.5ms interval request is sent automatically on every connect
- `BLE_SVC_L2CAP_Conn_Update()`: removed toggle logic; always requests 7.5ms (6 × 1.25ms)

**`client/STM32_BLE/App/app_ble.c`**
- `Connection_Update()`: changed from 50ms to 7.5ms

### On-connect sequence (server side)

```
connection_complete_event()
  → aci_gatt_clt_exchange_config()   [MTU 247]
  → schedule CFG_TASK_LINK_CONFIG_ID

LinkConfiguration() [task]
  → hci_le_set_data_length(251, 2120)  [DLE]
  → hci_le_set_phy(2M)                 [waits for PHY update complete]
  → schedule CFG_TASK_CONN_INTERV_UPDATE_ID

BLE_SVC_L2CAP_Conn_Update() [task]
  → aci_l2cap_connection_parameter_update_req(7.5ms, 7.5ms)
```

### On-connect sequence (client side)

```
connection_complete_event()
  → GATT_CLIENT_APP_Discover_services()
  [after PROC_GATT_ENABLE_ALL_NOTIFICATIONS]
  → Connection_Update() [task] → aci_gap_start_connection_update(7.5ms)
  → auto-TX starts
```
